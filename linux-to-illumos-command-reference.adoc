== Purpose

This is a practical reference to common Linux commands and their illumos counterparts. It is organized by task, not by a claimed universal popularity ranking: no single authoritative “top 250 Linux commands by usage” list exists.

[IMPORTANT]
====
Command availability and options vary by illumos distribution and release. Helios, SmartOS, and OpenIndiana should not be assumed to provide identical tools. Check the target system's manual pages before using commands that modify configuration, storage, services, or security settings.
====

Legend:

* *Same / similar* — the command exists and its basic purpose is familiar; options may differ.
* *Different* — use the listed illumos equivalent or a different workflow.
* *Optional* — the command may need to be installed.

=== Important process-troubleshooting differences

Linux `top` is commonly replaced by illumos `prstat`:

[source,shell]
----
prstat
prstat -a
prstat -L -p PID
----

Linux `strace` has a close illumos counterpart in `truss`:

[source,shell]
----
truss -p PID
truss -f /usr/bin/true
----

Check `man truss` for options supported by the installed release.

For process file descriptors and sockets, use:

[source,shell]
----
pfiles PID
fuser /path/to/file
----

=== Storage examples

[source,shell]
----
# Show filesystem capacity

iostat -En

# Inspect disks and disk configuration

# List configurable devices

# Inspect ZFS pool health
zpool status

zfs list

zfs get all pool/dataset

For Oxide/Helios, learn ZFS pools, datasets, snapshots, checksums, resilvering, and fault diagnosis in addition to the Linux `lsblk`/`mount` workflow.

=== The important networking difference: `ip` versus `ipadm` and `dladm`

On Linux, you may use:

[source,shell]
----
ip addr show
ip link show
ip route show
----

On illumos, use:

[source,shell]
----
# IP interfaces and addresses
ipadm show-if
ipadm show-addr

# Data links and physical interfaces
dladm show-link
dladm show-phys

# Routing table
netstat -rn

# Interface information
ifconfig -a
----

`ipadm` and `dladm` are separate administration interfaces for IP configuration and data links. Persistent configuration and interface properties are managed differently from Linux.

=== Learn SMF instead of translating every `systemctl` command

illumos uses the *Service Management Facility (SMF)*. Start with:

[source,shell]
----
# List services
svcs -a

# Find services that need attention
svcs -xv

# Inspect a service
svcs -l svc:/network/ssh:default

# Enable a service
svcadm enable svc:/network/ssh:default

# Disable a service
svcadm disable svc:/network/ssh:default

# Restart a service
svcadm restart svc:/network/ssh:default

# Inspect service configuration interactively
svccfg
----

The service identifier above is an example. Verify the actual FMRI on your distribution. SMF tracks service dependencies and failure states, not just process state.

On an IPS-based distribution, the command family is typically:

[source,shell]
----

# Install a package
pkg install package-name

pkg list

# Show package information
pkg info package-name

# Review configured publishers

----

These commands apply to IPS-based systems, not necessarily every illumos derivative or Helios deployment. Confirm the actual environment before installing software or changing packages.

== Practical recommendation

For a RHEL administrator moving toward illumos/Helios, prioritize `svcs`/`svcadm`, `ipadm`/`dladm`, `prstat`, `truss`, `pfiles`, `iostat`, and ZFS. These are among the most important practical differences from common Linux administration workflows.
